---
title: "Pre-production checklist"
description: "Production gates for standalone and VentStream Cloud-managed engine workloads."
---

Use this checklist before placing a standalone or Cloud-managed VentStream
workload on a production data path. VentStream operates the Cloud management
plane; customers remain responsible for connector access, workload sizing,
secrets, persistence, and data-path validation in their infrastructure.

<Warning>
Do not expose the native WebSocket or GraphQL subscription listeners to untrusted
clients yet. The current handshake requires a token but does not validate tenant
and subject authorization. Production realtime authorization remains a blocker.
</Warning>

## Blocks production

| Gate | What must be true |
| --- | --- |
| **Release images** | The protected-tag workflow publishes immutable multi-architecture image digests with SBOMs, provenance, signatures, and a strict vulnerability threshold. Retain a successful release run and its evidence before production promotion. |
| **Realtime authorization** | Expiring credentials are validated; tenant and subject claims are enforced before subscription; publish and subscribe permissions are separate. Required before untrusted realtime exposure. |
| **Metrics and alerts** | Prometheus scrapes `/metrics`; alerts cover heartbeat, DLQ growth, cursor lag, agent disconnects, failed operations, certificate renewal, email delivery, and database saturation. |
| **Real-data parity and soak** | Run beside the system being replaced and record document parity, bootstrap time, mutation-to-sink latency, memory, cursor age, retries, and DLQ behavior under real load. |
| **Failure and recovery drills** | Prove process/node/source/sink/control-plane failures, certificate renewal and revocation, backup restore, and rebootstrap against stated RPO/RTO targets. |
| **Security review** | Validate tenant isolation, authorization, mTLS, session/token handling, secret storage, network policy, image/dependency/IaC scans, and incident procedures. |

## Engine checklist

- Pin images by digest and promote the same digest between environments.
- Keep canonical `ventstream.yaml` non-secret; inject credentials from an
  approved secret manager.
- Run exactly one active replica for each CDC workload and give it a unique
  replication slot, server ID, consumer group, or connector cursor identity.
- Persist connector cursor, join, DLQ, and reconciliation state and test PVC
  loss/recovery behavior.
- For Postgres or MySQL production projections that require bounded memory, use
  SQL denormalization mode and index every join/FK lookup first.
- Add a metrics scraper, alerts, log retention, resource limits, NetworkPolicy,
  and a PodDisruptionBudget for replicated realtime gateways.

## Cloud-managed workload checklist

- Generate deployment values with `ventstreamctl agents manifest` so the chart,
  managed image digest, gateway addresses, and identity references come from the
  active Cloud installation profile.
- Allow outbound access to the enrollment and control gateways without exposing
  source databases, sinks, or engine health ports publicly.
- Retain managed-agent PVCs across upgrades. Test recovery from process and node
  restarts without deleting identity, cursor, or join state.
- Keep connector credentials in the workload secret manager and managed engine
  configuration non-secret.
- Confirm the CLI profile is scoped to the intended organization and environment
  before configuration or lifecycle changes.
- Verify runtime status, operation history, metrics, alerts, DLQ behavior, and
  rollback against representative data before production cutover.

## Already implemented

- PostgreSQL, Neo4j, MongoDB, MySQL/MariaDB, and Kafka/Redpanda CDC sources.
- OpenSearch/Elasticsearch sink, persisted cursor/join state, idempotent writes,
  DLQ handling, lifecycle operations, reconcile, and rebootstrap.
- Native WebSocket and GraphQL subscriptions over NATS/JetStream or Redis
  Streams; native WebSocket also supports live-only NATS Core delivery.
- Built-in verified accounts, rotating refresh sessions, recovery, signing-key
  rotation, optional enterprise OIDC, mTLS workload identity, and audited Fleet
  operations.
- Canonical engine configuration, immutable Fleet revisions, validation, apply,
  and rollback.
- Managed-agent and standalone deployment paths for Kubernetes, plus native
  engine binaries for supported platforms.
