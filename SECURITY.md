# Security Policy

## Supported versions

Security fixes are applied to the latest released minor version. Older
pre-1.0 releases may require an upgrade to receive a fix.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability.

Use GitHub's private vulnerability reporting flow from the repository
`Security` tab. Include:

- the affected version or commit;
- the deployment mode and enabled roles;
- a minimal reproduction;
- the expected and observed security boundary; and
- any known impact or workarounds.

Reports are acknowledged as soon as practical. Valid reports are investigated
privately, assigned a severity, and coordinated through a fixed release before
public disclosure.

Never include production credentials, customer records, private keys, or
unredacted logs in a report.
